# Mobile protocol fixtures

Cross-platform fixtures for the Companion mobile protocol. They cover canonical JSON, Ed25519 signatures, SAS words, and HPKE envelopes. Every key and token-shaped value in this directory is test data.

## Files

- `fixtures.json`: deterministic protocol vectors generated by `generate.mjs`.
- `generate.mjs`: regenerates and verifies the Node vectors.
- `swift/swift-consume.swift`: checks hashes, signatures, SAS output, and tamper rejection with CryptoKit.
- `swift/swift-jcs.swift`: checks the RFC 8785 canonical JSON implementation.
- `swift/swift-vectors.swift`: opens the selected RFC 9180 HPKE vectors.
- `swift/swift-cross.swift`: checks Node-to-Apple and Apple-to-Node envelopes.
- `hpke/node-vectors.mjs`: verifies the selected official HPKE vectors.
- `hpke/cross-seal.mjs` and `hpke/node-open.mjs`: regenerate and open the cross-platform envelopes.

The runtime EFF wordlist is stored at `src/mobile/eff_large_wordlist.txt`. Its SHA-256 digest is checked by `src/mobile/wordlist.js` and the test suite.

## Verify

Run from the repository root:

```sh
node fixtures/mobile-protocol/generate.mjs
node --test test/mobile-fixtures.test.js
```

On macOS with the Swift toolchain:

```sh
cd fixtures/mobile-protocol
swiftc -O swift/swift-consume.swift -o /tmp/qm-swift-consume
/tmp/qm-swift-consume

cd hpke
npm ci
curl --fail --location --proto '=https' --tlsv1.2 \
  --output vectors-full.json \
  https://raw.githubusercontent.com/cfrg/draft-irtf-cfrg-hpke/5f503c564da00b0687b3de75f1dfbdfc4079ad31/test-vectors.json
node node-vectors.mjs
swiftc -O ../swift/swift-vectors.swift -o /tmp/qm-swift-vectors
/tmp/qm-swift-vectors
swiftc -O ../swift/swift-jcs.swift -o /tmp/qm-swift-jcs
/tmp/qm-swift-jcs
swiftc -O ../swift/swift-cross.swift -o /tmp/qm-swift-cross
/tmp/qm-swift-cross
node node-open.mjs
```

The full RFC 9180 vector file is fetched rather than stored in this repository. `hpke/node-vectors.mjs` checks its expected SHA-256 digest before use.

`cross.json` and `apple-sealed.json` use fresh ephemeral keys when regenerated, so their bytes can change. The assertions they cover remain the same.
